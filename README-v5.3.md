# TechStore 5.3 — Web Push, encrypted offline drafts and server hardening

## Notifications
- Supabase Edge Function techstore-push is deployed. It uses pinned web-push@3.6.7, encrypted VAPID delivery, a fixed allowlist of browser push hosts and a generic notification payload (no PII, amounts or order details).
- VAPID key pair and worker token are generated and stored in Supabase Vault; only service-role RPCs access them. No secret is in GitHub. pg_cron invokes the worker every minute via pg_net. Queue claims are leased, delivery retries bounded, stale subscriptions deleted, expired endpoints removed, jobs expire. Push delivery is at-least-once, not exactly-once.
- User opens Device notifications while signed in, enables browser permission, registers the subscription, then queues a test. On iPhone install the PWA to Home Screen and use a supported iOS version. A registered subscription is tied to a live Supabase session. Sign out disables the local subscription; revoked/expired sessions are excluded from future claims. A previously dispatched notification can still arrive after sign out. The test button queues a request, not proof of delivery.
- Product alert events, new guest requests (authorized staff), and legacy account notifications trigger generic push jobs. The worker does not send until the device opts in. Provider/device restrictions apply.
- Verified SQL registration, queue, exclusive lease, completion, unsubscribe, secret access denial; cron successful and worker HTTP 200 with no real subscribed device. No real mobile notification delivery tested.

## Offline sync
- Offline sync center for owner, cashier and stock roles. Set a separate 14+ character local passphrase while online. IndexedDB stores an AES-256-GCM/PBKDF2-encrypted snapshot and up to 100 operation drafts. No customer personal data or access/refresh tokens in this vault. Cross-tab compare-and-swap prevents accidental overwrites. Password stays in page memory while unlocked; lock before leaving a shared device. Password cannot be recovered.
- Supported drafts: central single-product cash POS (owner/cashier), central count (owner/stock), branch stock transfer and cash sale (owner). Snapshot covers up to 5000 products and 30000 branch stock rows. Projected quantities account for prior drafts.
- Offline drafts are NOT final invoices or confirmed payments. Never deliver goods or book money as confirmed before the server accepts the transaction. Reconnect, unlock and sign in as the same account/role. Replay when connected while page open, or press Sync now. It uses stable request IDs and exact stock/price preconditions, atomically records stock and sale, stops on conflict, supports explicit rebase or discard of non-ambiguous drafts. Unknown outcomes must retry the same ID. Server authorization is independent of local role. Vault persists across restarts; no background financial sync when app is closed.
- Backend SQL tests passed POS, duplicate retries, changed stock conflict, count, branch transfer and snapshot; pure JS projection/role/oversell checks passed. No real IndexedDB/browser E2E or full multi-device load test. Not full offline ERP: customer orders, repair, accounting, documents, payment and other modules still need connection. Offline vault and service worker need real device testing. Local storage eviction or password loss can lose drafts.
- No real data written by rollback tests.
