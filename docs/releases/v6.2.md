# TechStore 6.2 — organization, staff, suppliers and store identity

## Implemented
- Reorganized cloud feature JavaScript under modules/, release documentation under docs/releases/. Updated HTML script tags, service worker cache, Node static allowlist, package checks and test file references together. Legacy demo entrypoints remain at their existing paths. Git history retained.
- Staff attendance with server timestamps, one open shift, own records, owner overview. Owner configures monthly salary and commission, generates one statement per completed month. Commission currently uses configured terms at creation and non-refunded cash invoices issued by that employee; later changes/refunds do not automatically adjust an issued statement. Not payroll payment or legal payroll/tax compliance.
- Limited staff-specific deny/allow within existing roles: new sale invoice, new repair invoice, receipt, repair intake for cashier; supplier statement read for stock staff. Server triggers enforce these named workflows. Legacy quick POS, other roles and operations are not comprehensively covered.
- Supplier purchase statement and recorded payments with overpayment/idempotency checks; owner branch revenue/cost/gross margin report from existing branch sale events. Separate supplier subledger, no automatic cash posting or full consolidated accounting.
- Store identity: name and logo shared with new invoices, bilingual tagline, accent color in cloud header/interface. PWA manifest name/icon, older demo and existing invoices remain unchanged.
- Separate public Supabase Storage bucket for new catalog JPEG images (up to four per product, compressed in browser), product gallery mapping, and public catalog merge. Owner-only uploads; public image URLs are intentionally public. Old embedded images retained; removing from a gallery does not delete the underlying file. Unreferenced objects require owner-side cleanup. No automatic migration or real upload/browser verification.
- SQL rollback tests passed staff attendance, statement access, restricted invoice denial, supplier payment/idempotency/overpayment, public identity/gallery reads and denied anonymous writes. Storage metadata insert policy tested with rollback, not actual image delivery. JavaScript syntax, URL allowlist and HTML/SW/server path consistency checked. No authenticated end-to-end tests or actual payroll payments.
- Partial returns and installment cancellation remain pending; previous full cash refund and installment invoice workflows unchanged. Full cross-module authorization and consolidated accounting remain pending. Previous security warnings and external provider dependencies remain.
