# TechStore 6.3.6 — protected workspace reads and legacy return guard

No new sections. Workspace reads for me, stock, customers, account and legacy records now use a dedicated authenticated RPC checking the existing active-session and MFA policy, role and individual read permissions. The staff permission list adds 13 read restrictions, with the existing supplier read restriction also applied to supplier records. These are restrictive only, not role grants. Cashiers receive projected stock data without cost and order records without purchase cost. Customer account responses are limited to their own orders, points, warranties, repairs and notifications. Denying reads needed by a form can prevent that form loading; no automatic override. No data or account deletion.

The legacy commit guard now also blocks owner-initiated legacy returns and changing/removing existing loyalty entries, preventing a second return path or accidental deletion of earned-point history. The integrated invoice and branch return workflows remain unchanged.

SQL rollback tests passed cashier cost privacy, cross-role access denial, per-employee read restriction, isolation of customers and loyalty, invalid session denial, owner legacy return denial, loyalty history preservation and stale revision conflict. JavaScript syntax, mock HTTP routing and script/cache consistency passed. No permanent test fixtures. No authenticated real-browser or multi-device concurrency test.

Important: direct old Edge GET endpoints remain deployed with their previous coarse role rules. This release protects the new workspace read API, not all direct legacy API calls; it is not a complete authorization fix. Newer specialized registers retain their existing permission rules. No Edge redeployment. Legacy debt/installment accounting and full physical reconciliation remain incomplete. Security advisor warnings and MFA actual-device testing remain outstanding.
