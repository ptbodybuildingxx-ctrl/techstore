# TechStore 4.0 | النسخة السحابية الأولية
تم الحفاظ على نسخة المتجر وإدارة المحل السابقة في index.html، مع إضافة workspace.html وserver.mjs. هذه نسخة تطوير وليست مراجعة أمان أو اعتماداً تجارياً.

## التشغيل
يتطلب Node.js 24 أو أحدث. لا توجد حزم npm خارجية.
```sh
npm run check
npm test
ADMIN_EMAIL=owner@example.com ADMIN_PASSWORD='REPLACE-WITH-A-STRONG-UNIQUE-PASSWORD' npm start
```
افتح http://localhost:8080. استخدم كلمة مرور خاصة لا تقل عن 12 حرفاً. لا تحفظها في GitHub أو ملفات الكود. في Windows عيّن المتغيرات من PowerShell قبل التشغيل. قاعدة SQLite في DATA_DIR (افتراضياً data/). بيانات المتجر المركزية تبدأ فارغة. من حساب المدير افتح لوحة الإدارة السابقة، أدخل المنتجات أو استعد نسخة JSON موثوقة ثم اضغط «حفظ مركزي». لا تنشر بيانات تجريبية كأنها مخزون فعلي.

## الميزات
- تسجيل دخول وجلسة HttpOnly وSameSite، كلمات مرور مشتقة بـ scrypt، صلاحيات محددة على الخادم وإيقاف حسابات الموظفين.
- مساحة عمل مركزية ومخزون مشترك، تحديث ذري للطلبات والبيع والمشتريات والجرد والمرتجعات. حفظ مركزي يدوي للواجهة القديمة مع رقم مراجعة؛ تعارض التعديلات يرفض الحفظ. لا مزامنة offline تلقائية.
- الموردون والمشتريات، الديون والأقساط وتسجيل الدفعات، الأجهزة المستعملة (سجل)، الباركود Code 39 للأكواد المدعومة والجرد، المرتجعات. نقطة بيع مركزية سريعة لمنتج واحد؛ POS القديم يدعم عدة منتجات عبر حساب المدير والحفظ المركزي.
- حسابات العملاء، طلبات COD وحجز المخزون، الكوبونات والعروض، نقاط ولاء عند التسليم (لا استبدال نقاط)، إشعارات داخل الحساب، كفالة وصيانة مرتبطة بمعرف العميل. ربط الصيانة والكفالات القديمة بالحسابات يتم يدوياً؛ لا تُكشف بواسطة بريد غير موثّق.
- منشئ صفحة رئيسية مرئي: إضافة أقسام، ترتيب بالسحب أو الأزرار، قائمة، ألوان، صور، مسودات، معاينة، نشر واستعادة إصدار. لوحة CMS القديمة محفوظة؛ لا يوجد محرر حر لكل صفحة.
- مستشار شراء حسب الميزانية والمواصفات، تحليل أرباح تقريبي، اقتراح سعر بتكلفة × 1.25، وتوقع نفاد من آخر 30 يوم. هذه قواعد حسابية، ليست نموذج ذكاء اصطناعي خارجياً.
- نسخ SQLite عند التشغيل وكل 24 ساعة (14 نسخة على نفس القرص). يلزم نسخ مشفرة خارج القرص واختبار استعادة دوري. لاستعادة نسخة: أوقف الخادم، احتفظ بملفات DB/WAL/SHM الحالية، انسخ نسخة موثوقة إلى techstore.sqlite وأعد التشغيل.
- واجهة عربية/إنكليزية. العمليات المركزية الجديدة مقومة بالدولار؛ الليرة وسعر الصرف في الإدارة السابقة. لا دفع إلكتروني فعلي أو WhatsApp API أو Web Push.

## نشر الخادم
GitHub Pages يستضيف ملفات ثابتة فقط؛ لا يشغّل server.mjs أو SQLite. يوجد Dockerfile وrender.yaml لإعداد خدمة Node على Render مع قرص دائم؛ الخطة والقرص قد يكونان مدفوعين. أنشئ خدمة/Blueprint من هذا المستودع، اضبط ADMIN_EMAIL وADMIN_PASSWORD كأسرار وPUBLIC_ORIGIN بعنوان HTTPS النهائي (دون شرطة أخيرة). إذا تغير عنوان الخدمة حدّث PUBLIC_ORIGIN. لا تستخدم خدمة تخزين مؤقتة. راقب النسخ الاحتياطية والمراقبة واختبر HTTPS. لم يتم تشغيل استضافة حية من خلال رفع الكود.
## ما قبل الإنتاج
مراجعة أمان مستقلة، اختبار متصفح وموبايل، مصادقة ثنائية وتحقق البريد واسترداد كلمات المرور، حدود طلبات مناسبة للبنية التحتية، سياسة خصوصية، تدقيق محاسبي، نسخ خارج الموقع، إدارة حذف/تعديل السجلات، تكامل دفع وواتساب، ومزامنة offline مع حل تعارضات. افصل بيئة الاختبار عن الإنتاج. لا تضع بيانات العملاء في المستودع العام.
