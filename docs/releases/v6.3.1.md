# TechStore 6.3.1 — integration and stabilization, no new sections

Existing POS now uses existing invoices. Offline cash sale replay uses the same transactional invoice issuance, permission and request ID. Delivered confirmed web orders create a paid invoice in the same revision commit, using the reserved sale's cost and allocating the actual total after discounts to lines; no second stock deduction. Existing sales cannot be altered or removed by the legacy snapshot API. New legacy POS and purchase writes are rejected; reload current workspace. Return via original invoice; legacy return screen is read-only. Web orders are paid COD at delivery confirmation, with no warranty assigned by default. Existing direct legacy checkout still differs from membership checkout.

Purchases update stock at weighted average cost and register supplier payable atomically. Owner records actual supplier cash payments against the bill; central cash and payable are updated once. New payroll statements accrue expense/payable; owner confirms actual cash payment once. Branch journal pairs mirror into the existing business ledger with unique source references; branch cash stays separate from central cash closing. Reports use the integrated ledger, with existing inventory forecasting retained. No new navigation sections. Central cash closure blocks new central invoices, supplier postings and payroll; branch cash is separate. Historical source tables were empty when the migration ran; no historical import. Do not record the same cash movement manually again.

Rollback SQL tests passed purchase idempotency, supplier payment, offline invoice replay, branch sale, payroll accrual/payment, cash and stock reconciliation; also confirmed order delivery, original reserved cost, discounted partial refund, revision conflict and protection from snapshot sale deletion. Test fixtures rolled back. JavaScript syntax and script/cache path consistency checked. No actual browser session or physical printer test. Request IDs cover identical retries; browser memory-only pending IDs do not guarantee retry identity across reloads. Still outstanding: full authorization of legacy operations, full offline support, warranty/loyalty handling for web orders, branch expense/returns/settlement, complete accounting/tax compliance, security advisories and device E2E. No claim of production certification.
