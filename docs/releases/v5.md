# TechStore 5.0 Professional — additive cloud release

Existing Auth accounts, catalog, legacy workspace, dark/light theme and older roles remain intact.
New modules are available from Professional center. They use row-level security and separate normalized entry/grant tables in Supabase. Owner grants apply to these new modules only. Financial records are append-only; corrections require a new entry. The new cash/quote/voucher/payroll/bank/repair/shipping/branch registers are independent/manual, not a general ledger, branch-separated stock system, invoice posting engine, or carrier integration. Memberships and alert requests are stored, without automatic discounts/delivery. Reviews are private submissions, not public verified reviews.

Customers can save favorites and builds, submit reviews/alert requests, compare catalog specifications and calculate a build total. There is no automatic compatibility or FPS prediction in the new comparison page. Existing local builder remains in the explicitly isolated demo/legacy UI. Voice and camera barcode recognition depend on browser APIs and device permissions. CSV and browser printing work from the currently visible records. Owner JSON export includes current legacy workspace, accessible legacy records, profiles, grants and new modules, but is not a transactional, encrypted or scheduled off-site backup and excludes Auth secrets. Store securely.

## Optional real AI
The deployed `techstore-ai` Edge Function calls OpenAI Responses API (gpt-5.4-mini) only if both `OPENAI_API_KEY` and `TECHSTORE_AI_ENABLED=true` are configured as Supabase Edge Function secrets. Never commit keys. Use a dedicated API project with a budget. A verified active account is required; each role has specific permitted tasks. The database enforces up to ten requests per user and sixty per project per UTC day, including attempted upstream requests. User consent is required. No automatic writes or AI actions; prompts and limited role-appropriate context are sent to the provider. Do not send personal data. The key was not configured or exercised by this release.

## Verification and limitations
Database tests ran in rolled-back transactions: admin creation, financial archive denial, branch archive/restore, audit, customer isolation, staff read-only versus create grant, AI per-user quota. JS syntax and mocked client/section checks passed. No authenticated browser end-to-end run, live AI call, SMTP delivery, hardware print or camera test. Security advisor still flags leaked password protection disabled; private service-only tables intentionally have RLS without public policies.
Still required: guest checkout, branch stock isolation, old-module granular permissions, accounting integration and proper posting, full inventory import and offline sync, public review moderation, automatic alerts/WhatsApp/Web Push, payment/carrier integrations, repair images/signatures/parts integration, real compatibility/FPS, off-site scheduled backups, production security review, domain and native app. No existing data was removed.
