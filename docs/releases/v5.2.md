# TechStore 5.2 — branch operations, guest checkout, repairs and loyalty
This additive release retains existing accounts and workspace. New SQL migrations are applied on Supabase. No production sales, customers or products were seeded by tests.

## New pages
- **Branch stock & journal** (owner only): transfer from central warehouse to branch, between branches, and back; independent quantities and weighted cost; cash sale at catalog price; immutable debit/credit pairs. Transactions lock the workspace, check stock, use idempotency IDs and increment the revision. Branch sales are separate from legacy invoices/reports/returns. Dashboard totals cover recent 200 events; journal shows latest 400 pairs. General accounting consolidation, tax rules, branch staff assignments, branch returns and full journal pagination remain.
- **Repair evidence & approvals**: staff before/after photos and central spare-parts consumption, linked customer access, approval at the displayed estimate, no staff impersonation; idempotency IDs for retry. Maximum 12 photos per ticket, compressed JPEG. Approval is an authenticated record, not a legally certified signature, and does not change the old repair status automatically. Photos and part costs are access controlled; the UI chooses available public catalog parts. Parts are not automatically posted to the branch journal.
- **Product alerts**: one-time in-account notifications from actual price decreases and restocking of visible catalog products, triggered by workspace writes. Customer can mark their own alerts read. No OS push or WhatsApp delivery.
- **Guest requests**: no account required for submitting COD request with consent; price is calculated on server, no stock reservation until staff verify contact and approve. Guest tracks with a private random code; no PII in tracking result. Limits 3 submissions per phone hash and 100 globally per hour. This is an abuse-reduced manual review flow, not verified contact/CAPTCHA protection or electronic payments. Requests need retention/privacy procedures.
- **Membership & wholesale pricing**: owner assigns tier and configures discount 0–30%, points per USD and maximum point redemption 0–20%. All discounts/redemption default to zero. New signed-in checkout applies max(tier,coupon), optional points, server total confirmation, stock reservation and idempotency. Points redeemed are refunded when legacy order status changes to cancelled. Legacy direct order endpoint still exists and does not enforce the new rules; the new workspace UI uses the new checkout RPC.
- **Offline**: browser session cart draft, bounded public catalog cache (up to 300 products, 7 days). No personal details or financial data cached by this feature. Offline checkout and financial mutation are not allowed; reconnect and revalidate. This is not full offline business reconciliation.
- Encrypted manual backup now includes recent branch register and repair evidence. It is not complete or scheduled/off-site; guest requests, membership state, all historical events and alerts are not covered by this export.

## Verification
SQL tests executed against the configured Supabase database inside rolled-back transactions: branch transfer/sale, idempotency and no oversell; spare part decrement, exact estimate approval and linked-customer isolation; automatic price/restock notification with no duplicates; guest pricing, no premature reservation, private tracking, owner review; membership quote, points debit/refund, changed total rejection and role checks. JavaScript syntax and mocked views passed. No end-to-end authenticated browser session, payment, real notifications, hardware or full production load test completed. All new sensitive tables use RLS with no direct public access; controlled RPCs check role and live session for protected actions. Public guest RPC is intentionally callable only for restricted submit/status actions. SQL advisor informational RLS warnings are expected on private RPC-only tables. Leaked-password protection remains disabled; legacy Edge Function live-session update remains pending from 5.1. No assurance of zero vulnerabilities.

## Remaining dependencies and gaps
Electronic payment provider account, keys and webhook configuration; WhatsApp Business and Web Push registration/permissions, message policy and consent; OpenAI API key and billing; SMTP delivery and Auth security settings/MFA; encrypted off-site backup destination and scheduled restore drills; native mobile app and domain; comprehensive accounting, branch staff/returns, full offline reconciliation, measured FPS and multi-image product gallery. Do not use live financial data until security and end-to-end acceptance tests are completed.
