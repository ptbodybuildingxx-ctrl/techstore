# TechStore 6.3.2 — confirmation and consistency

No new navigation sections. Existing request-ID-based online mutations (13 scopes: invoices, receipts, deposit/expense, adjustment/refund, purchase/supplier payment, branch transfer/sale, repair evidence and member order) now claim an IndexedDB slot per authenticated account and scope before sending. The slot stores only an ID, canonical SHA-256 payload fingerprint, account ID, scope and timestamp, not the request body. Identical retries on the same browser reuse the ID even after reload. Changed payload is blocked while a prior operation is unresolved. Web Locks serialize the request across tabs where available; IndexedDB atomic claim remains the fallback. Confirmed response clears the slot; ambiguous network/response errors retain it. Explicit SQL rejection clears a newly claimed slot. Existing in-memory form guards reset on definite rejection or acknowledged confirmation. A conditional inline notice lets users query the server for their own recorded operation and acknowledge the reference; absence is not definitive failure and does not release the ID. If exact input cannot be reconstructed and the result remains unknown, manual reconciliation is required. Clearing browser data or changing device loses local state; successful response followed by user-initiated new sale is not deduplicated. Offline encrypted queue remains separate. No automatic resend without confirmation. Guest order tracking and legacy mutation routes are not covered by this change.

Server status RPC checks active session and account ownership, returns only status/reference; anon cannot execute. Repair part insertion after final invoice is rejected atomically, including stock rollback. SQL transaction tests passed confirmation, scope/account isolation, fake-session denial, duplicate issuance and part rollback. JavaScript behavioral simulation with in-memory storage passed lost response, identical retry, changed payload denial, SQL error handling, malformed confirmation and account isolation. Actual IndexedDB, concurrent browser/device testing, full browser E2E, remaining legacy authorization, branch returns/expenses, loyalty and security configuration are still not complete.
