# TechStore 6.3.5 — branch history, loyalty and reconciliation

No new navigation sections. Branch stock now searches original sales by full/partial sale reference, product ID/name and branch, using stable 50-row cursor pagination. Returnable quantity includes every prior return. The recent activity table still displays 200 events, but the summary uses net revenue and cost from all branch events. Owner-only search and totals. The product name is the current catalog name, not a historical snapshot.

Linked direct cash invoices and optional linked branch cash sales earn one point per full USD, matching the existing web-order earn rate. A private source register tracks earned, target and posted points; returns proportionally reverse earned points using cumulative monetary value. Source and workspace postings are transactional; retries do not duplicate points. Unlinked sales, installments and redemption at a physical POS are not covered. The previous web-order loyalty rules remain. No automatic historic backfill.

Existing accounting page includes nine read-only reconciliation checks for invoice revenue/initial payment, supplier bills/payments, payroll, mirrored branch journals, branch stock movement totals, sale references and negative central stock. These checks are limited to those relationships, not a physical stock/cash count, historical ledger audit, or proof of completeness of all transactions. No automatic correction of detected mismatches.

Rollback SQL tests passed 205 branch sales across pages, search for an old sale, return, net totals and nine reconciliation checks; direct and branch cash point accrual, partial reversal, retry and changed linked-customer denial. JavaScript syntax, branch form markup, reconciliation markup and cache paths checked. Real authenticated browser, multi-device concurrency, full legacy read permissions and unification of legacy Edge endpoints remain unverified/incomplete. MFA policy remains optional and existing accounts/records preserved. No Edge redeploy. Existing Supabase security warnings are not addressed in this maintenance step.
