# TechStore 6.3.3 — reconciliation and legacy permissions

No new navigation sections. The existing branch stock page now accepts inspected resalable partial or full returns against an original branch sale. Original cumulative quantities, sale price and recorded cost determine the refund and cost reversal; stock returns to the original branch, and branch cash (not central cash) is debited. Owner only; retry ID enforced, over-return and insufficient branch cash rejected. The integrated ledger and supplier/branch summary show net revenue and cost. The UI selects sales in the latest 200 branch events; older returns need a further history/pagination improvement. The returned stock uses weighted-average cost based on the original event's rounded total cost. No damaged goods or warranty exchange workflow added.

Delivered web order invoice adjustments reconcile earned and redeemed loyalty points proportionally to cumulative returned monetary value. Reversal and restoration entries are append-only through this flow; repeated returns/retries do not duplicate points. Negative point balance is possible if earned points were already spent; existing checkout caps redeemable balance at zero. This does not extend loyalty to branch sales or unrelated invoices, or handle zero-value invoice refunds.

Nine additional per-employee restrictions apply within role boundaries: inventory, purchase, supplier, order, repair, warranty, debt, installment and used-goods writes. Legacy snapshot commit validates changed record categories and active actor, checks configured denials, prevents old customer checkout and non-admin legacy return writes, and restricts workspace changes. Purchase, technician evidence, offline count and guest review have corresponding server checks. Existing cashier invoice/receipt and intake controls remain. Legacy GET routes still use coarse role checks; full read authorization and strict token/session enforcement on old Edge endpoints need a reviewed server release. No Edge redeploy performed. Individual denials do not grant new role privileges. Existing data and accounts retained.

SQL rollback tests passed branch partial/full returns, net cash/revenue/cost, same-branch stock, retry and status, excess return denial, denied legacy inventory, proportional loyalty restoration/reversal and identical retry, denied guest review. JS syntax, mock branch return markup/net amounts and cache path consistency passed. No actual authenticated browser or printer/device E2E. The public pg_net extension is not relocatable; do not drop/recreate it on live production without isolated dependency review. Supabase leaked-password protection is an Auth dashboard setting available on Pro and above; not enabled by this update. Both advisor warnings remain pending. No security certification.
